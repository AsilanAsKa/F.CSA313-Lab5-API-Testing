## 1. Лабораторийн зорилго

Энэхүү лабораторийн ажлын зорилго нь Postman болон Newman ашиглан REST API системд тест хийх, тест кейс боловсруулах, тестийн үр дүнг шалгах юм. Оюутан бүртгэлийн API системийг ашиглан зөв болон буруу оролтын нөхцөлүүдийг туршив.


- Node.js хувилбар: v22.22.2
- Newman хувилбар: 6.2.3


## 2. API системийн мэдээлэл

Үндсэн хаяг: `http://localhost:3000`

| HTTP арга | Endpoint | Зориулалт |
|---|---|---|
| PUT | `/students/:id` | Оюутны мэдээлэл үүсгэх, шинэчлэх |
| PUT | `/courses/:id` | Хичээлийн урьдчилсан нөхцөл тохируулах |
| GET | `/courses/:id` | Хичээлийн мэдээлэл авах |
| POST | `/registrations` | Оюутныг хичээлд бүртгэх |
| GET | `/registrations` | Бүртгэлийн мэдээлэл авах |

## 3. Тест дизайны боловсруулалт

### 3.1 Сонголтууд ба эквивалент ангиллууд

| Сонголт | Боломжит утгууд | Тайлбар |
|---|---|---|
| Оюутны төлөв | Идэвхтэй, идэвхгүй, байхгүй | Оюутны бүртгэл болон төлөвийг шалгах |
| Үзсэн хичээлүүд | Шаардлага хангасан, хангаагүй, хоосон | Урьдчилсан нөхцөл шалгах |
| Хичээлийн ID | Байгаа, байхгүй | Хичээлийн бүртгэл шалгах |
| Урьдчилсан нөхцөл | Бүгд хангасан, зарим нь дутуу, байхгүй | Хичээлийн шаардлага шалгах |
| Хүсэлтийн өгөгдөл | Зөв, талбар дутуу, JSON буруу | Хүсэлтийн форматыг шалгах |

### 3.2 Тестийн спецификаци

| № | Тестийн тохиолдол | Оролтын нөхцөл | Хүлээгдэх HTTP төлөв | Хүлээгдэх үр дүн |
|---|---|---|---|---|
| 1 | Амжилттай бүртгэл | Идэвхтэй оюутан, байгаа хичээл, урьдчилсан нөхцөл хангасан | 201 | `OK` |
| 2 | Оюутан байхгүй | Оюутны ID бүртгэлгүй | 200 | `ERROR_NO_STUDENT` |
| 3 | Идэвхгүй оюутан | Оюутан байгаа боловч идэвхгүй | 200 | `ERROR_INACTIVE_STUDENT` |
| 4 | Хичээл байхгүй | Хичээлийн ID бүртгэлгүй | 200 | `ERROR_NO_COURSE` |
| 5 | Урьдчилсан нөхцөл хангаагүй | Оюутан CS201 хичээлийг үзээгүй | 200 | `ERROR_PREREQUISITES` |
| 6 | Шаардлагатай талбар дутуу | Оюутны ID эсвэл хичээлийн ID байхгүй | 400 | `ERROR_BAD_REQUEST` |
| 7 | Буруу JSON | Хүсэлтийн JSON формат алдаатай | 400 | `ERROR_BAD_JSON` |
| 8 | Хязгаарын нөхцөл | Урьдчилсан нөхцөлгүй хичээлд бүртгүүлэх | 201 | `OK` |
| 9 | Нийтийн API | JSONPlaceholder хэрэглэгчдийн мэдээлэл авах GET хүсэлт | 200 | Хэрэглэгчдийн массив |
| 10 | Давхар алдаа: Оюутан ба хичээл байхгүй | Оюутны ID болон хичээлийн ID хоёулаа бүртгэлгүй | 200 | `ERROR_NO_STUDENT` |
| 11 | Давхар алдаа: Идэвхгүй оюутан ба prerequisite дутуу | Оюутан идэвхгүй, урьдчилсан нөхцөл хангаагүй | 200 | `ERROR_INACTIVE_STUDENT` |

Амжилттай бүртгэлийн үед хариу JSON дотор `registrationID` талбар байх бөгөөд тоон утгатай эсэхийг шалгасан. Тогтмол ID утга тулгаагүй.

## 4. Postman Collection

Тестүүдийг `lab05-collection.json` файлд хадгалсан.

Collection нь 11 Folder, нийт 20 хүсэлттэй. Үүнд:
- Амжилттай бүртгэл
- Оюутан байхгүй үеийн шалгалт
- Идэвхгүй оюутны шалгалт
- Хичээл байхгүй үеийн шалгалт
- Урьдчилсан нөхцөл хангаагүй үеийн шалгалт
- Буруу хүсэлт болон JSON формат
- Урьдчилсан нөхцөлгүй хичээлийн хязгаарын тест
- JSONPlaceholder нийтийн API тест

Тест бүрт шаардлагатай оюутан болон хичээлийн мэдээллийг тохируулах хүсэлтүүдийг тухайн Folder дотор байрлуулсан.

Мөн зориудаар буруу шалгалтын нөхцөл үүсгэсэн `lab05-collection-fail.json` файлыг тусад нь бэлтгэсэн. Энэ тест амжилттай бүртгэлийн HTTP 201 хариуг буруу 200 гэж шалгадаг.

## 5. Newman ашиглан тест ажиллуулах

Newman суулгах:

```bash
npm install -g newman
```

Үндсэн тест ажиллуулах:

```bash
newman run lab05-collection.json 2>&1 | tee results/newman-pass.txt
echo "exit=${PIPESTATUS[0]}"
```

Зориудаар алдаатай тест ажиллуулах:

```bash
newman run lab05-collection-fail.json 2>&1 | tee results/newman-fail.txt
echo "exit=${PIPESTATUS[0]}"
```

Сервер унтарсан үеийн тест ажиллуулах:

```bash
newman run lab05-collection.json 2>&1 | tee results/newman-down.txt
echo "exit=${PIPESTATUS[0]}"
```

## 6. Тестийн бодит үр дүн

| Тестийн төрөл | Хүсэлтийн тоо | Шалгалтын тоо | Алдаатай | Exit code |
|---|---:|---:|---:|---:|
| PASS | 20 | 39 | 0 | 0 |
| Зориудаар FAIL | 3 | 4 | 1 | 1 |
| Сервер DOWN | 16 | Холболтын алдаа | - | 1 |

**PASS:** Сервер ажиллаж байх үед нийт 39 шалгалт амжилттай болж, алдаа гараагүй.

**FAIL:** Буруу хүлээгдэж буй HTTP төлөв заасан тул нэг шалгалт амжилтгүй болсон. Newman алдааг зөв илрүүлсэн.

**DOWN:** Серверийг зогсоосон үед `ECONNREFUSED 127.0.0.1:3000` алдаа гарсан. Энэ нь API сервертэй холбогдож чадаагүйг илэрхийлнэ.

## 7. Нийтийн API тест

Нэмэлтээр дараах нийтийн API-г шалгасан.

`GET https://jsonplaceholder.typicode.com/users`

Дараах 3 шалгалтыг хийсэн:
1. HTTP төлөв 200 байх.
2. Хариу өгөгдөл массив хэлбэртэй байх.
3. Эхний хэрэглэгчийн нэр `Leanne Graham` байх.

JSONPlaceholder нь зөвхөн GET хүсэлтээр өгөгдөл авдаг учраас нэмэлт setup шаардлагагүй байсан. Харин өөрийн API дээр өгөгдөл үүсгэж, өөр өөр нөхцөлөөр турших шаардлагатай байсан.

## 8. Дүгнэлт
Энэхүү лабораторийн ажлаар Postman болон Newman ашиглан API системд тест хийж сурлаа. Бүртгэлийн API-д зориулан зөв болон буруу оролтын нөхцөлүүдийг тодорхойлж тест кейс боловсруулсан. Эквивалент ангилал болон хязгаарын нөхцөлийн аргыг ашигласан. Тестийн нөхцөлүүдээс давхар алдааны үед аль алдааг түрүүлж шалгахыг тодорхойлох нь хамгийн их бодол шаардсан. Оюутан байхгүй болон хичээл байхгүй гэсэн хоёр алдааг хамтад нь үүсгэхэд API эхлээд `ERROR_NO_STUDENT` буцаасан. Идэвхгүй оюутан болон prerequisite дутуу нөхцөлд `ERROR_INACTIVE_STUDENT` алдаа түрүүлж шалгагдах ёстой. Харин амжилттай бүртгэл болон prerequisite хангагдсан нөхцөлүүдийг шалгасан.

Үндсэн Newman тест ажиллахад 39 шалгалт бүгд амжилттай болсон. Зориудаар буруу хүлээгдэж буй үр дүн тохируулахад Newman алдааг илрүүлсэн. Сервер унтарсан үед `ECONNREFUSED` холболтын алдаа гарсан. JSONPlaceholder нь зөвхөн GET хүсэлтээр өгөгдөл авдаг тул тест хийхэд илүү хялбар байсан. Харин өөрийн API дээр өгөгдөл үүсгэж, өөр өөр нөхцөлөөр турших шаардлагатай байсан. Туршсан нөхцөлүүдэд API-ийн хэрэгжүүлэлтийн гэнэтийн алдаа илрээгүй. Харин зориудаар буруу хүлээгдэж буй үр дүн тохируулахад Newman үүнийг амжилттай илрүүлсэн. Ингэснээр API-ийн ажиллагаа болон алдааг илрүүлэх талаар практик мэдлэгтэй боллоо.
